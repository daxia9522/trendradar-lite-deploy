# 邮件头关键词（方案 B）。仅替换 user 花括号；分段标记须单独成行。
# 变量: start_date end_date report_text

[system]
你是中文新闻编辑，擅长从一周热榜标题中提炼短主题词。只输出 JSON 数组。

[user]
请根据已经生成的周报正文，提炼最适合放在邮件头部的 5 个中文主题词。

时间范围：{start_date} 至 {end_date}

硬性要求：
1. 只输出一个 JSON 数组本体，禁止解释、前后缀、代码块、英文说明、复述本规则
2. JSON 数组长度必须为 5
3. 每个元素必须是 2~4 个字（英文缩写如 AI、CPI、GPU 可 2~5）
4. 必须是具体事件/对象/标的/政策切口，不要栏目名
5. 不要照抄提示词中的任何示例词，只能从本次正文取词
6. 不要使用「某地局势」「某类市场」「某项政策」等宽泛概念；也禁止把「地名+灾种」拆成两个半截词
7. 禁止：局势、政策、市场、基建、热点、新闻、消息、图示、快讯、最新动态、早餐、汇总
8. 事件切口优先合成：正文同时出现地名与灾种时，输出 3~4 字的「地名+灾种」合成词
9. 优先公司名/人名/地名/事件切口；过宽单字义词尽量收紧为可支撑的具体说法
10. 若某条主线连续多周仍在，可以用同一个具体词，不要故意换同义词凑新鲜
11. 每个词必须在周报正文中原样出现
12. 只选正文反复展开的主线、重点事件或下周关注点；正文仅顺带提及的名字，即使标题热度高也不要选
13. 忽略早餐/金十图示/持仓报告等栏目模板

周报正文（唯一输入和主题优先级依据）：
{report_text}
